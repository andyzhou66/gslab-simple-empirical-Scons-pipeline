# CLAUDE.md

This file provides guidance to Claude Code (claude.ai/code) when working with code in this repository.

## Quick Commands

**Build the analysis:**
```bash
cd analysis
python run.py
```

**Build the paper/slides:**
```bash
cd paper_slides
python run.py
```

**Build everything in a specific directory:**
```bash
cd analysis
python run.py build/path/to/directory
```

**Build a single target and its dependencies:**
```bash
cd analysis
python run.py build/path/to/file.txt
```

**Use caching mode (faster builds after first run):**
```bash
python run.py mode=cache
```

## Repository Structure

This is a GSLab research project template organized around reproducible data analysis and paper production:

### Top-level directories
- **`analysis/`** — Data processing, analysis scripts, and statistics. Outputs go to `analysis/release/`.
- **`paper_slides/`** — Paper and presentation generation. Inputs are manually copied from `analysis/release/` to `paper_slides/input/`.
- **`config/`** — Shared configuration, dependency setup, and SCons executable.

### Subdirectory structure (both `analysis/` and `paper_slides/`)
Each main subdirectory has:
- **`source/`** — All scripts that produce output (Python, R, Stata, MATLAB, LyX, LaTeX, or shell scripts).
- **`build/`** — Build artifacts generated by SCons (organized to mirror `source/` structure).
- **`release/`** — Final outputs intended for release; these are copied to GitHub or shared destinations.
- **`SConstruct`** — SCons build definition for this subdirectory.
- **`run.py`** — Wrapper that executes `config/scons/scons.py` with arguments passed through.

### Configuration files
- **`config_global.yaml`** — Versioned configuration: gslab_python version, build/source directory paths, prerequisite checks, repository logging settings. Applies to both `analysis/` and `paper_slides/`.
- **`config_user.yaml`** — Local, unversioned user preferences: executable paths (Python, R, Stata, MATLAB, LyX, LaTeX), cache directory location, release destination. Generated from template if missing.

## Build System

This project uses **SCons** (Software Construction tool) for dependency tracking and reproducible builds:

- **`run.py`** scripts are thin wrappers around the packaged SCons (`config/scons/scons.py`).
- **SConscript files** define builders for different languages (Python, R, Stata, MATLAB, LyX, LaTeX) and the "Anything builder" for shell commands.
- **Logging** — Each builder produces a log in its output directory; all logs are concatenated to `release/sconstruct.log` at the end.
- **MD5-timestamp decider** — Rebuilds only when content changes, not just timestamp.

### Custom builders available (uncomment in SConstruct to enable)
- **`BuildPython`** — Executes Python scripts
- **`BuildR`** — Executes R scripts (requires R executable and dependencies)
- **`BuildStata`** — Executes Stata scripts (requires stata_executable in config_user.yaml)
- **`BuildMatlab`** — Executes MATLAB scripts
- **`BuildLyx`** — Compiles LyX documents to PDF (paper_slides)
- **`BuildLatex`** — Compiles LaTeX directly (paper_slides)
- **Anything builder** — Executes arbitrary shell commands for custom workflows

## Configuration Setup

Before building for the first time:

1. **Install dependencies:**
   ```bash
   pip install -r config/requirements.txt
   ```

2. **Unzip SCons (packaged with repo):**
   ```bash
   unzip config/scons.zip -d config/scons  # (Manual on Windows)
   ```

3. **Optional: Install language-specific dependencies:**
   - **R:** `Rscript config/config_r.r`
   - **Stata:** `statamp -e config/config_stata.do` (adjust executable name as needed)
   - **MATLAB:** Follow instructions in [gslab_matlab](https://github.com/gslab-econ/gslab_matlab) README for YAML parser setup

4. **First build** — When you run `python run.py`, if `config_user.yaml` doesn't exist, it will be copied from the template. Edit it to specify your local executable paths and cache directory (optional).

## Key Architecture Patterns

### Dependency coupling between subdirectories
- **`analysis/` outputs → `paper_slides/` inputs:** Manually copy desired files from `analysis/release/` to `paper_slides/input/`. This intentional decoupling allows coauthors to run the paper without re-running expensive analysis.
- Alternative (lighter but more fragile): use symlinks or point to `analysis/release` in `paper_slides` config_global.yaml.

### Large files
- **Versioned:** Tracked with git-lfs; add to `.gitattributes` and list under `look_in` in config_global.yaml.
- **Unversioned in release:** Store in `release/lg/` (automatically in .gitignore); included in local releases but not GitHub.
- **External datasets:** Document download instructions in README; optionally specify local paths in config_user.yaml (so paths don't vary across users).

### Logging and diagnostics
- **Build logs:** Each builder produces `sconscript.log` (or custom `log_ext`); all are merged into `release/sconstruct.log`.
- **Repository state:** `release/state_of_repo.log` tracks file sizes and git-lfs usage; `release/state_of_input.log` records input directory contents (paths listed under `input` key in config).

## Troubleshooting

**`config_user.yaml` not found** — SCons will copy the template automatically on first run. Delete and re-run to reset.

**Executable not found** — Check that executables (Python, R, Stata, etc.) are:
1. Installed and in PATH
2. Listed in `config_user.yaml` under `executable_names` (only needed if not in PATH)
3. Have `prereq_checks` enabled in config_global.yaml

**SCons cache stale** — If mixing SCons versions (>= 2.5.0 have different cache format), delete the cache directory and rebuild.

**Build fails with dependency issues** — Run with `python run.py --debug` for full traceback. Check that all source files exist and SConscript rules are correct.
